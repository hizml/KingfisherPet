# 59 个版本,7 条纪律:一只翠鸟教会我的事

> 本文是系列第三篇。前情提要:2018 年同事分享过一只 Windows 桌面小鸟(不到 1MB 的日文 EXE,至今躺在我微信收藏里),去年我想再养一只,发现它没有 Mac 版——干脆自己做,Mac 原生 Swift + Windows Tauri 双平台,大半代码与 AI 结对完成。系列第一篇讲完整故事,这是技术干货线。

项目叫「翡」,一只住在你菜单栏的翠鸟。它会俯冲捕鱼、会把屏幕啄裂、会在你没喂它的时候自己找乐子;听到你放歌它会闭嘴,看到你全屏看片它会带着自己拉的屎一起消失。

听起来是玩具。但从 v1.0 到 v1.4.59,213 个 commit,它把我按在地上摩擦了两百多次。这篇文章不是成功学,是**每次翻车之后,项目里沉淀下来的一条纪律**。它们现在都躺在仓库的 `docs/DEV_NOTES.md` 里,写着「违者回炉」。

每条纪律背后都是真实事故,commit 还在,可以查。

---

## 纪律一:说"修好了"之前,先分清你处在哪一档

项目内部对"完成"有四档黑话:

> **编译过** / **场景过** / **快照过** / **仅推理**

编译过,只代表语法对了;场景过,是真实环境里跑出了预期行为;快照过,是有截图/日志为证;仅推理,是"代码看起来应该对"。

这条纪律是用一次闪退换的。做"放音检测"(系统在放歌时鸟不叫)时,我基于一个私有框架写了查询,编译通过,顺手就报了"已修"。用户装上,放歌,鸟叫了一声,然后**整个应用闪退**。三份崩溃报告摆在一起才看清:私有 API 的真实函数签名是两个参数,代码按一个参数调,寄存器里的垃圾被当对象释放,直接 SIGSEGV。

编译器验证的是 ABI 之上一层,而这类问题住在 ABI 之下。从此规矩:**"仅推理"不得报"已修"**,报告里必须写清楚是哪一档。听起来像废话,但它逼着你在说"好了"之前停半秒——那半秒经常能救一条命。

## 纪律二:同一个 bug 修第二轮还没修好,禁止继续修,先铺可观测性

"全屏看片时鸟要隐身"这个功能,我们排障了整整六轮。

前三轮都在换检测思路:看最顶窗口、看任一屏上窗口、看前台 App 的全部窗口——几何法三条路全部阵亡。第四轮换辅助功能的窗口属性,授权、链路全通了,用户实测:**Chrome 全屏,鸟岿然不动**。

第五轮开始前立了新规矩:不许再猜。先在检测函数里铺了每 9 秒一拍的观测日志,把"前台 App 名字、窗口数、每个窗口的全屏属性值、窗口矩形"全部打出来。用户切了一次全屏,日志里赫然写着:

```
前台=ZCode 窗口1个 [w0:fs=false [156,33 1200x800]]
```

前台是 ZCode——一个 Electron 应用,窗口矩形、属性、枚举**全部正常读到**。而同样的查询对着 Edge 永远返回"-25212 无值"。真相浮出:**macOS 的 `focusedApplication` 查询对 Chromium 内核的应用一律返回空**,对原生应用却一切正常。用户全屏看片用的恰恰全是浏览器——这个检测从第一天起就从未工作过,而它伪装成"授权问题"骗了我们四轮。

第六轮换掉取前台的通道,问题消失。

这就是纪律二的含义:**连修两轮失败,说明你对系统的模型是错的,再修一百轮也是换着花样撞墙**。这时候唯一该写的代码是日志——让系统亲口告诉你它长什么样。

## 纪律三:从运行时对象上"顺便拿"的值,可能是假的

给设置窗口加滚动条,连翻三次车,一次比一次迷惑。

内容明明是 320 宽,界面却显示 640 宽、还能横向拖拽。第一反应是布局代码错了,改,不对;钉死常量,还不对。最后在布局完成处打了一行"几何快照"日志,真相是:**`window.contentView!.bounds` 在窗口布局早期返回的是 640×560——恰好是逻辑尺寸的两倍**。所有从它取值的控件全被悄悄放大了一倍,而视口是真实的 320,于是内容溢出、横向可滚。

修完这一条,顺手总结出"几何三律"进了 DEV_NOTES:

1. **几何值钉常量**,不从运行时对象上顺便拿;
2. **改容器尺寸必须平移子视图**——坐标系不会自动重映射,不然控件永远在 frame 外,"滚到底也看不到";
3. **改任何配置文件前,先 grep 谁在消费它**。

第三律是同一晚踩的另一个坑:给"啄屏幕"开关加中文文案,规规矩矩查了本地化文件格式、插进了正确的位置——但项目的文案系统根本是代码里的内置字典,那个 `.strings` 文件**没有任何代码在读**。插对了地方,插进了一个平行宇宙。

## 纪律四:幽灵 API——"这个方法存在"是你想象出来的

Windows 端有一个贯穿全项目的坑:屏幕缩放。在 200% 缩放的远程桌面上,鸟的坐标全部错位。

日志里所有尺寸都对,唯独缩放系数恒等于 1。翻代码,罪魁是一行:

```ts
const m = await (win as any).currentMonitor();
```

Tauri 2 的 `currentMonitor` 是**模块级函数**,不是窗口方法;窗口对象上没有这个方法,`as any` 把类型检查捂死,调用返回 `undefined`,兜底逻辑给了默认值 1。于是在 100% 屏上一切正常,200% 屏上整个坐标系统静默崩塌。

比 bug 更值得记的是它的诞生机制:**写代码时"记得有这个 API",类型系统本可以拦住,而 `as any` 把唯一的哨兵撤了**。从此 CI 里加了一条硬检查:全仓库禁 `as any`。这类问题还有一个变种兄弟——"以装的包为准":文档说有这个函数不重要,`node_modules` 里装的版本里有才算数。

## 纪律五:发出去的版本号,泼出去的水

某个周五连发三版修同一个破壳动画死循环,v1.4.28 发完我顺手把 tag 删了重打,准备覆盖发一次"干净的 28"。

用户一句话点醒:"为啥版本号不更新?"

对啊。**tag 删了重打,用户已经装走的那个 v1.4.28 还活着**,再发一个同号版本,出问题时所有人分不清彼此在说什么。版本号的价值恰恰在于它不可变——它是排障对话里的坐标轴。

于是立规矩:**tag 推过即固定,修复递增新号**。听起来损失了"完美递增的版本序列",但那本来就是幻觉;真实世界的版本序列本来就是充满 "28a 修 28 的火" 的样子,假装它完美只会害排障的人。

## 纪律六:跨平台代码,必须过目标平台的编译检查——哪怕你手边没有那台机器

一段 Windows 用的代码,引用了一个常量的新路径。我在 Mac 上跑 `cargo check`,全绿,提交,发版。

CI 的 Windows 构建当场爆炸:`PCWSTR` 在 0.61 版的依赖里搬了家,而我 Mac 上的检查**因为 cfg 条件编译静默跳过了这段代码**——绿灯是假的,它根本没检查这段。

Mac 上跑 Linux 检查、本地跑 CI 检查,这类"看起来过了"最危险,因为它同时满足了你的侥幸心理和你的截止时间。规矩:**跨平台代码必须 `--target` 目标平台过一遍编译**,本机装交叉 target 只要一行命令。那条 CI 抓到的导入错误,如果没有这条规矩,会一直潜伏到用户装上包才炸。

## 纪律七:自动化脚本失败了,后面所有命令必须停

最惭愧的一次。给设置窗做滚动,我临时在代码里塞了 6 个假设置项和一段"启动 3 秒自动弹窗"的验证代码,验证完写脚本清理。清理脚本的匹配串写错了一个字("验证项"写成了"验证"),断言失败,脚本退出——

**但发版命令照跑了。**

因为那条命令链是 `python 清理.py` 换行 `swift build` 换行 `git tag`,不是 `&&`。清理失败无声无息,v1.4.52 带着 6 个"验证项 1~6"和自动弹窗出了门。用户打开设置,看到一堆假开关。

事故不大,但性质恶劣:**失败被静默吞掉后,流程的每一步都在放大它**。从此两条铁律:清理/校验脚本失败必须中止整个发版链(`&&` 串起来,或脚本里直接 exit);所有"勿提交"的临时代码,必须带一个 CI 能 grep 到的标记。

---

## 写在最后

这 7 条没有一条是从书上看来的,每一条背后都是用户的一句"还是不行"。

有意思的是它们的共性:**几乎全部关于"诚实"**——对自己诚实时说清验证到了哪一档,对系统诚实时先让它开口说话再动手,对工具诚实时承认绿灯可能是假的。写代码这件事,难度从来不在打字,在于抵抗"应该没问题了"的诱惑。

这些纪律现在管着一只鸟。顺便说,它最近学会了新本事:发现新版本时,它会把自己的"检查更新"菜单项改名成"发现新版本"——不弹窗,不吵你,就静静换个名字等你来看。这大概是这段人机协作最好的隐喻。
